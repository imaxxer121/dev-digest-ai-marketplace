# Plugin guidelines

The package boundary follows a coherent consumer and release lifecycle.
Paved-path owns stack practices, research-tools owns source discovery,
architecture-review owns independent structural checks, and sdd-engineering
owns workflow coordination. Project-specific instructions stay in the consumer.

Manifests declare name, SemVer, description, author, license and dependencies.
Use root-relative component conventions, complete supporting resources and
namespaced references. Each Markdown agent declares inherited model and a
minimal tool list. Read-only profiles do not have Bash, Edit, Write or delegation.
The runtime's physical sandbox remains necessary; metadata is not enforcement.

Load skills on demand instead of repeating their bodies in every agent.
Do not put credentials, absolute workstation paths, repository-specific imports,
personal journals or generated artifacts into reusable packages. Document the
target path contract and missing-test behavior. Keep actual inference evidence
separate from CLI/schema/static checks.
